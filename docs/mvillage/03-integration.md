# 03. 실서비스화 연동 스펙 (Integration)

> 프로토타입(목데이터) → 실서비스 전환에 필요한 연동 지점·스키마·시스템 요구사항. · 갱신 2026-10-02
> 목표: **화면·플로우·다국어는 유지**하고 데이터 레이어만 교체. (OhMyHotel × Modern Village Lifestyle 한국 GSA)

---

## 1. 아키텍처 원칙

현재는 컴포넌트가 `mocks/mvillage/*`를 직접 import. 실연동 시 **서비스 레이어**(`services/mvillage/*`)를 두고 컴포넌트는 인터페이스만 바라보게 한다(오마이트립 본 클론 `services/api/*`, OHMYGOLF `services/golf/*` 패턴 동일).

```
[컴포넌트] → [services/mvillage/*.ts (인터페이스)] → ┬ mock 어댑터(현재)
                                                     └ ELLIS/OMH/파트너 API 어댑터(실서비스)
```

교체 시 컴포넌트·화면·다국어 레이어 수정 없이 어댑터만 바꾼다.

---

## 2. mock → API 교체 지점

| 현재(목) | 대체(실) | 담당 시스템 |
|---|---|---|
| `data.ts` `BRANDS / brandByKey` | 브랜드 마스터 API | M Village 브랜드 자산 |
| `data.ts` `COLLECTIONS` | 컬렉션(머천다이징) 구성 | OMH 큐레이션 |
| `data.ts` `PROPERTIES / propsByCollection` | 시설 목록·상세 API | ELLIS 시설/상품 |
| `ROOM_META` × `fromKRW` (요율 합성) | **객실 플랜·실시간 요율/재고 API**(날짜·인원별) | 요금·재고 엔진 |
| `MVillageBooking` `setDone()` (상태 전환) | **결제(PG) + 예약 생성 API** | PG·예약 |
| `MVillagePartner` `setDone()` | 제휴 리드 접수(CRM/메일/카카오 채널) | B2B/영업 |
| `translations.ts` (UI+콘텐츠+스토리) | 상품/브랜드 **다국어 필드** + 번역 운영 | CMS/번역 |
| `images.ts` seed→CC 풀 | 자사 이미지 CDN | 이미지 CMS |
| `wonKR()` 고정 ₩ 포맷 | 통화·환율 정책(KRW 기준 판매면 유지 가능) | 환율/정산 |

## 3. ELLIS / OMH 스키마 (신설·매핑 요청)

[02 데이터 모델]을 API 계약으로 바꿀 때 필요한 M Village 특화 필드:

### 3.1 브랜드 마스터 (신규 도메인)
- `key, name, tierLabel, tierRank, tone, target, tagline, blurb, cities[]`
- `facilities`(전체 시설 수), `omhOpen`(오마이호텔 채널 개방 수 · allotment)
- **브랜드 스토리**(다국어) — 브랜드 상세 페이지 콘텐츠(현재 `BRAND_STORY` 4언어 목값)
- 브랜드 키비주얼 이미지(히어로)

### 3.2 컬렉션(머천다이징)
- 목적별 묶음(`key, name, purpose, message, brandKeys[], tone, icon`) — 브랜드/시설을 **목적 단위로 재구성**하는 큐레이션 규칙. OMH 운영이 소유.

### 3.3 시설·상품
- 시설 기본(`id, name, brandKey, collectionKeys[], city, blurb, features[]`)
- 배지(한국 인기/베스트셀러/신규/오픈예정) — 머천다이징/판매 데이터 기반
- **객실 플랜**: 타입·최대투숙·조식·퍽스·**실시간 요율·잔여실**(현재 `ROOM_META`×배수 합성 → 실제 플랜/재고로 교체)

### 3.4 요율·재고·예약 (핵심 — 실시간 OTA)
- 날짜·인원·객실타입별 **실시간 요율 조회**(현재 `fromKRW × mult × nights × rooms`)
- **재고(allotment) 조회·홀드·확정** 트랜잭션(오버부킹 방지)
- 세금·수수료 정책(현재 10% 가정) → 국가/채널별 정산 규칙
- 예약 생성 → 예약번호·바우처 발급(현재 `MV{ID}{num}` 목값)

### 3.5 제휴(B2B) 리드
- 제휴 유형·회사·담당자·연락처·내용 → **CRM/영업 파이프라인** 또는 카카오 채널/메일 자동 접수
- 그룹 단위 요율·시즌 공동 기획전 문의 라우팅

## 4. 결제(PG) 연동

- 현재 `/mvillage/book/[id]`는 **UI 시뮬레이션**(카드/KakaoPay/NaverPay/Toss 선택만, [즉시 예약] → 완료 화면). 실 결제·실 재고 차감 없음.
- 필요: PG 연동(국내/해외 카드·간편결제), 결제 후 **예약 생성 API**(재고 확정·바우처), 실패/취소/부분환불, 영수증.
- 보안: 결제/개인정보는 서버·PG에서 처리(프론트 비밀정보 미저장). 현 프로토타입은 카드 입력 필드조차 없이 결제수단 **선택 UI**만 존재 → 민감정보 전송 0.

---

## 5. 회원/인증

- 현재 예약·제휴는 **비로그인**(입력 폼만). 언어 선택만 `localStorage(mv-lang)`.
- 필요: 오마이호텔 회원 SSO, 예약 내역·바우처의 **계정 동기화**(마이페이지), 제휴 담당자 계정.

---

## 6. 다국어(i18n) / 콘텐츠

- 현재: **UI·콘텐츠·브랜드 스토리까지 4개 언어(ko/en/ja/zh) 번역 완료**(프로토타입 목번역). 고유명사(시설명·브랜드명)는 원형 유지.
- 필요: 번역을 **CMS/상품 다국어 필드**로 이관(운영팀이 직접 수정), 신규 브랜드/시설 추가 시 번역 워크플로. 통화·가격 표기 정책(현재 KRW 단일).
- 구조적 이점: `data.ts`(한국어 원본) ↔ `translations.ts`(오버레이) 분리 → API 전환 시 **원본은 상품 API, 오버레이는 번역 필드**로 자연스럽게 대응.

---

## 7. 이미지

- 현재: `images.ts`가 seed를 해시해 `/public/mvillage/img` **CC 스톡 풀**에서 선택(브랜드/시설 무관 범용).
- 필요: **M Village 자사 실사진**(브랜드 키비주얼·시설·객실), CDN·webp 최적화, `next/image` 도입 검토. 브랜드 상세 히어로는 브랜드별 키비주얼 필수.

---

## 8. 비기능/기술 고려

- **렌더링**: 현재 정적 export(SEO·CDN 유리). 실시간 요율·재고는 **CSR fetch** 또는 SSR/ISR 전환 필요 → 예약 라우트만 동적화 검토.
- **동적 라우트**: `brand/[key]`(7) · `book/[id]`(12)는 `generateStaticParams`로 정적 생성 중. 실시설 증가 시 ISR/온디맨드 생성 전략 필요.
- **성능**: 히어로 켄번스·스크롤 리빌은 `prefers-reduced-motion` 대응. 실이미지 도입 시 사이즈·webp 관리.
- **접근성**: 현 통과 수준 유지(키보드·라벨·h1·언어 `<html lang>` 동기화) — [04 문서].
- **분석/로그**: 전환 퍼널(배너→브랜드관→브랜드/시설→예약) 이벤트 설계 필요(현재 없음).

---

## 9. 최소 실서비스화(MVP) 우선순위 제안

1. 브랜드·컬렉션·시설 마스터 실데이터(ELLIS/OMH 스키마 신설·매핑)
2. 실시간 요율·재고 조회 + 객실 플랜 확정
3. 결제(PG) + 예약 생성·바우처 + 마이페이지 연동
4. 제휴(B2B) 리드 CRM/카카오 채널 연결
5. 번역 CMS 이관 + 신규 시설 번역 워크플로
6. 자사 실사진·실시간 환율(품질 고도화)
